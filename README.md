# 車機螢幕守衛 (ScreenGuard)

解決 JHY S17（Android 10）在**螢幕關閉時，按方向盤音量鍵會把螢幕喚醒**的問題。

行為：偵測到音量變化 → 開始倒數（預設 5 秒）→ 期間沒有其他操作就把螢幕關掉；
期間只要有其他操作（點螢幕、按其他鍵），就取消這次關螢幕（也可改成「重新計時」）。

因為不確定這台車機能用哪個 API 關螢幕，App 內放了 **12 種關螢幕方法的測試按鈕 + 兩種自動掃描**，
測出哪個有效之後，在「③ 正式行為設定」的下拉選單選它，正式邏輯就會用那個方法。

## 2026-07-26 車機實測結論

| 項目 | 結果 |
|---|---|
| 方法 A（無障礙鎖屏） | 螢幕會關，但是**真的斷電式關閉**，不能用 |
| 方法 B（lockNow） | 同上，不能用 |
| 方法 J（全黑覆蓋層） | **可用，已設為預設** |
| 音量事件 | 不走 AudioManager，但**車機音量條會發畫面事件**：`TYPE_VIEW_SELECTED pkg=com.ts.MainUI cls=SeekBar` |

A/B 之所以不合用，關鍵在於它們把車機帶回「螢幕真的關掉」的狀態，
而那正是**按音量鍵會被喚醒**的原始狀態，等於繞回原問題。
J 則是讓 Android 一直以為螢幕是亮的，MCU 沒有「要喚醒」這件事可做，
所以 J 不是備案，是這題唯一對的解法。

## 正式方案（按首頁最上面那顆「✅ 正式啟用」就套用）

| 設定 | 值 |
|---|---|
| 關螢幕方法 | J 全黑覆蓋層 |
| 觸發 | 只認車機音量條事件（`com.ts.MainUI` / `SeekBar`） |
| 螢幕亮起就倒數 | 關（已經抓得到音量，不需要這條備援，你自己開螢幕不會被蓋） |
| 輪詢音量 | 關（這台音量不走 AudioManager，輪詢是白工） |
| 其他操作 | 取消本次關螢幕 |
| 自動再黑 | 關（點掉黑幕後就讓你用，下次按音量再黑） |
| 診斷模式 | 關 |

音量條的 pkg / class 是可設定的（④ 進階觸發），車機改版換了元件名不用重編 APK。

> 注意：`TYPE_VIEW_SELECTED` 原本被歸類成「使用者操作」，且 `com.ts.MainUI` 不在忽略清單裡，
> 所以音量規則必須排在操作判斷**之前**，否則調音量會被自己判成操作、把倒數取消掉。

已經編好的檔案：`ScreenGuard.apk`（debug 簽章，可直接裝）。
- USB 隨身碟拷到車機安裝（車機要允許「未知來源」）
- 或 adb：`adb install -r H:\AppDemo\Car\ScreenGuard.apk`

## 在車機上的測試步驟

### ① 先開權限
1. **開啟無障礙設定** → 找到「車機螢幕守衛」→ 開啟。**這一項一定要開**，
   不開的話音量偵測、方法 A 都不會動。
2. 其餘三個按需要再開：裝置管理員（方法 B）、懸浮視窗（方法 J）、修改系統設定（方法 H/I）。

### ② 一個一個按，找出能關螢幕的方法
每個按鈕按下去，**螢幕若立刻變黑就是這個有效**。醒來後看畫面最下面的「④ 事件記錄」，
每次呼叫的回傳值都會寫在裡面（車機沒接 adb 也看得到）。

| 代號 | 方法 | 備註 |
|---|---|---|
| A | 無障礙 `GLOBAL_ACTION_LOCK_SCREEN` | Android 9 以上原生 API，**優先試這個** |
| B | 裝置管理員 `lockNow()` | 有效但可能會叫出鎖定畫面 |
| C | 反射 `PowerManager.goToSleep()` | 需系統簽章，通常會被擋，但值得一試 |
| D | root：`input keyevent 26`（POWER） | 車機有 root 才會過 |
| E | root：`input keyevent 223`（SLEEP） | 同上 |
| F | 免 root：`input keyevent 223` | 通常權限不足，順手測 |
| G | 寫 0 到 `/sys/class/backlight/*/brightness` | 會自動列出實際存在的節點 |
| H | 把系統休眠逾時改成 5 秒 | 車機若有照規矩跑逾時就會自己暗掉 |
| I | 系統亮度歸零 | 背光還在，只是全暗 |
| J | 全黑覆蓋層 + 視窗亮度 0 | **保底方案，一定有效**（假關螢幕，點畫面解除） |
| K | 自訂廣播 | 在上面欄位輸入 action 再按 |
| L | Instrumentation 注入 POWER 鍵 | 需 INJECT_EVENTS，通常會被擋 |

另外兩個掃描工具：
- **自動掃描常見車機關螢幕廣播**：依序送出 18 個常見中國車機 ROM 的關螢幕 action，
  每個間隔 2 秒後檢查螢幕狀態，若某個之後螢幕真的關了，記錄裡會用 ★★ 標出來。約 40 秒，掃描時請不要碰螢幕。
- **掃描車機內含 screen/backlight 的系統元件**：把車機原廠 App 裡名稱含 screen、backlight、lcd、sleep、
  black、display 的 Activity/Receiver/Service 全列出來，點一下就直接對它發廣播或啟動它。
  很多車機原廠設定裡本來就有「黑屏」功能，這招常常能挖到。

> 方法 H / I 會改到系統設定，測完按「**還原被改掉的亮度／休眠逾時**」就會復原。

### ③ 測出來之後
1. 在「正式關螢幕要用哪個方法」下拉選單選中有效的那個。
2. 秒數預設 5，可改。
3. 「倒數中若有其他操作」預設是**取消，這次就不關螢幕**（照你原本的描述）；
   若想改成「停手後仍然關」就選重新計時。
4. 按「**模擬一次**」測完整流程：開始倒數，手不要碰，看 5 秒後會不會關。
5. 最後實際到車上按方向盤音量鍵驗證。

## 找出這台車機的音量訊號（診斷模式）

方向盤音量走 MCU 直接控功放，Android 端完全沒動靜，所以要先找出「按音量時 Android 這邊還有什麼會跟著動」。

1. 確認「診斷模式」開著（預設開）。
2. 按幾下方向盤音量鍵。
3. 回到 App 看「⑤ 事件記錄」，找 `[診斷]` 開頭的行，看有沒有東西跟音量同步出現：
   - `[診斷] 系統設定變更：content://settings/system/xxx` ← 車機把音量寫進系統設定
   - `[診斷] 視窗變化：xxx` ← 車機自己的音量條是一個會冒出來的視窗
   - `[診斷] 按鍵 keycode=…` ← 音量鍵有進到 Android
4. 找到之後填進「④ 進階觸發」：
   - 設定鍵那格填關鍵字（預設已填 `volume`）
   - 視窗那格填音量條的套件名
   按「儲存觸發設定」即可生效，**不用重編 APK**。
5. 三種都沒動靜的話，就代表音量完全在 MCU 內部處理，Android 不可能知道 ——
   那就維持現在的「螢幕亮起就倒數」，效果一樣達得到目的。

診斷模式很吵，找到答案後記得關掉。

## 音量偵測有五條路（同時開著）
1. 系統廣播 `android.media.VOLUME_CHANGED_ACTION`
2. **輪詢音量值**（每 300ms 比對 stream 0~9）
3. 無障礙的實體按鍵事件（音量鍵 keycode 24/25/164）
4. **系統設定 ContentObserver**（System / Global / Secure 全掛），鍵名含 `volume` 就算
5. **音量條視窗出現**（要在進階觸發填套件名）

再加一條備援：睡眠期間音量值有變 → 螢幕亮起時直接判定「這次是音量喚醒」。
JHY S17 實測 1~3 都抓不到，所以這台靠的是「**螢幕一亮就倒數**」（已預設開啟）。

## 誤判防護
調音量時系統會跳音量條，那個畫面變化不能算「使用者操作」，否則倒數會馬上被取消。
所以來自 `com.android.systemui` / `android` / `com.android.settings` 的畫面事件，
以及音量變化後 1.2 秒內的畫面事件，都不算操作。
若車機上還是有東西一直打斷倒數，記錄區會寫出是哪個 package，回報給我再加進忽略清單。

## 除錯
- App 內「④ 事件記錄」就是完整 log，可按「複製」丟給我看。
- 有接電腦的話：`adb logcat -s ScreenGuard`

## 觸發條件（主畫面的勾選項，**預設不勾**）

不勾（預設）＝只要偵測到調音量就開始倒數。

勾選「只有『調音量前螢幕是關閉的』才變黑」時，判斷式是：

```
音量事件進來時螢幕還是關的
  || 螢幕亮起不到 4 秒（＝就是這次音量把它喚醒的）
  || 目前在暗模式
```

- 螢幕關著 → 按方向盤音量 → 螢幕亮 → 符合 → 蓋黑幕 ✅
- 看地圖（螢幕一直亮著）→ 調音量 → 不符合 → 沒動作 ✅
- 黑幕被點掉後 → 調音量 → 不符合 → 不會再變黑，要再關一次螢幕才重新生效 ✅
- 用手指點亮螢幕後調音量 → 不符合 → 沒動作 ✅

已經在倒數中時，再調音量一律重新計時（不受這個條件限制）。

> 不要單靠「按過關閉螢幕」的旗標判斷 —— 旗標會殘留，會讓「用手指點亮螢幕後調音量」也被誤判。
> 主要判斷的是**音量事件當下的螢幕狀態**。

### 為什麼這台車機需要「暗模式」這個補丁

2026-07-27 實測：**手機**收得到 `ACTION_SCREEN_OFF/ON`，**JHY S17 收不到** ——
按車機的關閉螢幕只是切背光，Android 全程認為螢幕是亮的。
所以純看螢幕狀態的條件在這台永遠不成立，這也是為什麼這個勾選項預設關閉。

補救辦法跟找音量條一樣：開診斷模式按一次車機的關閉螢幕，從記錄找出那個按鈕的
畫面事件 pkg / class，填進「開發者設定 → ④ 進階觸發」的「關閉螢幕按鈕」兩格。
之後看到該事件就進入暗模式，勾選項才有作用。

暗模式的進入／離開：

| 進入 | 離開 |
|---|---|
| 收到 `ACTION_SCREEN_OFF`（手機會，這台不會） | 點掉黑幕 |
| 比對到「關閉螢幕按鈕」事件（需填設定） | 倒數期間碰螢幕 |
| 黑幕蓋上（含手動「立刻變黑」） | |

開發者頁狀態行會顯示「螢幕：亮著（已亮 N 秒）　暗模式：是／否」，方便確認。

## 讓黑幕更黑（LCD 背光問題）

黑幕只是把畫面畫成黑色，**LCD 的背光還是亮著**，晚上看起來會是灰的而不是全黑。
三個層次可以往下壓，由淺入深：

1. **視窗亮度覆寫**（不需權限）：`WindowManager.LayoutParams.screenBrightness`。
   `0f` 是 `BRIGHTNESS_OVERRIDE_OFF`，語意是「關背光」，有些機器真的會關、有些只壓到最低。
   舊版寫死 0.004f（＝最低亮度，不是關背光），現在預設 0 且可在開發者頁調整（單位千分比）。
2. **系統亮度歸零**（需「修改系統設定」權限）：蓋黑幕時把 `SCREEN_BRIGHTNESS` 設 0 並切手動模式
   （不切手動的話自動亮度會馬上把它拉回去），解除黑幕時自動還原。主畫面的「更黑」勾選項，預設開。
3. **直接寫背光節點**（需 root）：開發者頁的方法 G，`/sys/class/backlight/*/brightness` 寫 0。
   沒 root 就用不了。

> 安全機制：亮度被壓低期間如果 App 被系統殺掉，螢幕會一直暗著。
> 所以原值存在 SharedPreferences，服務被關掉時會還原，重新打開主畫面時也會偵測並自動還原，
> 開發者頁另有「還原被改掉的亮度／休眠逾時」按鈕。

## 兩個介面
- `MainActivity`（啟動時看到的）：只有「幾秒後變黑」＋「開始使用」＋「停止」。
  按開始使用會自動套用正式方案、缺權限會直接把你帶到該去的設定頁。
- `DevActivity`（主畫面右下角「開發者設定」）：原本的完整開發介面，
  12 種關螢幕方法、兩種掃描工具、全部細項開關、事件記錄都在這裡。

## 觸控偵測為什麼要另外做
無障礙事件只有在**元件自己回報**時才會發（點按鈕、捲動清單），
在車機桌面上單純滑一下手指，Android 不會發任何事件，所以「滑螢幕」抓不到。
解法是 `TouchWatcher`：掛一個 1×1、`FLAG_NOT_TOUCHABLE` + `FLAG_WATCH_OUTSIDE_TOUCH`
的隱形視窗，使用者碰螢幕任何地方都會收到 `ACTION_OUTSIDE`。
不吃觸控所以不影響車機原本操作，而且只在倒數那幾秒掛著。

## 專案結構
- `ScreenGuardService` — 無障礙服務：音量／操作偵測、倒數、執行關螢幕
- `ScreenOff` — 12 種關螢幕方法 + 廣播掃描 + 系統設定還原
- `BlackOverlay` — 保底的全黑覆蓋層
- `DiscoverActivity` — 車機系統元件掃描
- `MainActivity` — 設定與測試頁
- `Logx` — 畫面內記錄（同時寫檔，關螢幕後仍看得到）
